# Web ↔ mobile token parity — 2026-10-22

> Module-by-module comparison: see `2026-10-22-modules.md`.

- **Reference:** mobile `e6RBhSWdLlLinhceozYLYe`.
- **Compared:** web `VYNooSMqyhqJPom58kg8zV`.
- **Library:** both files use AOH UI/ShadCN, and it is the only library linked to either file.
- **Mode:** read-only.
- **Checks:** token values and roles, bound vs hardcoded colours, text styles, and status colours. There is no layout or screenshot comparison.
- **Data:** inventories in `inventory/`; findings in `reports/2026-10-22.json` and `register/drift-register.json`.

The severity rubric below is proposed. The `token-parity-audit` skill is not in the repo yet.
- **P1:** a colour that carries meaning (status or severity) differs between platforms.
- **P2:** the same role uses a different token or value, or one side uses a stale or hardcoded value where the other binds a token.
- **P3:** naming, scale or hygiene issues with little visible difference.

## Expected platform differences (not drift)

- **Control sizes:** mobile uses `size-button-lg/xl` and `size-input-lg` for touch targets. Web uses `size-button-sm`, `size-input-sm` and `size-formControll-sm`.
- **Spacing:** `spacing-xs` and `spacing-3xl` are used only on web.

## Excluded

- **System UI drawn by the OS:** `Android-nav-bar`, the keyboard and the keyboard kit.
- **Annotations:** annotations and flow arrows.
- **Web module title labels:** `#eeeeee` text in Inter 64.

These exclusions are proposed and listed in `config/module-map.json`.
