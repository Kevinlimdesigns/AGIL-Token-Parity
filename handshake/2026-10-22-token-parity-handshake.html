02What was checked

  • Scope: 8 web modules against their mobile pages. Each pair compares only the module's own content: the app shell is excluded on both sides (web header, tabs and map; mobile status bar, PTT bar and tab bar).
  • Checks: colour tokens by role, colours bound to tokens vs hardcoded, text styles, spacing and radius, shadows, stale bindings and shared AOH components. No layout or screenshot comparison.
  • Left out: the Android nav bar, the keyboard, annotations and flow arrows. Different control sizes are expected for touch targets, so they are left out too.
  • Read-only: nothing in Figma was changed. Source data and reports are in the AGIL-Token-Parity repo under reports/ and inventory/.

04Decisions needed from chern

Each card gives a recommendation. Write the decision in the blank; anything left blank stays open.

P1CHERN-DECISIONPAR-001

Which colours mean severity and status?

Mobile uses its own priority level/* tokens (critical #ef4444, high #fb923c, medium #facc15, low #38bdf8, minimal #a1a1aa). Web uses AOH icon-error, icon-warning, icon-info and the warning-muted family. No value matches, so the same incident looks different on each screen.

Recommendation: add five priority/* semantic tokens to AOH, with Light and Dark values, and use them on both platforms. Keep AOH error, warning and info for system messages.

P2CHERN-DECISIONPAR-002

What does web's orange mean?

Web hardcodes #f97316 (Orange/500) in all 8 modules: geofence shapes and draft pins. AOH has no token for it. Mobile's nearest colour is priority level/high #fb923c.

Recommendation: name what it represents, then either give it an AOH token or fold it into the priority tokens from PAR-001.

One focus ring

Mobile uses border-focusRing-sidebar (Zinc/400, a token meant for the sidebar) and border-interactive-focus (Sky/500). Web uses border-focusRing (Blue/500).

P2CHERN-DECISIONPAR-005

Card corners: 8px or 12px

Web cards use radius-card (12px). Mobile cards use radius-dialog (8px) or a hardcoded 8 or 20.

Recommendation: use radius-card for cards on both platforms, and keep radius-dialog for dialogs only.

DecisionDate
P2CHERN-DECISIONPAR-008

One avatar

Web uses the AOH Avatar with size-avatar-*. Mobile uses a local Avatar filled with comms/avatar-surface #2a3f5c.

Recommendation: mobile moves to the AOH Avatar at mobile sizes. If the dark surface is wanted, add it to AOH as a semantic token.

DecisionDate
P3CHERN-DECISIONPAR-010

Icons on dark surfaces

Web uses icon-invers; mobile uses icon-onColor. The values differ.

Recommendation: use icon-onColor on brand or status fills and icon-invers on inverse surfaces, on both platforms.

DecisionDate
P3CHERN-DECISIONPAR-012

Spacing of 10

Both platforms use an unbound gap of 10, which is not on the AOH scale (8 and 12 are). It appears about 1,000 times on mobile and about 2,000 on web.

Recommendation: keep the AOH scale and move both platforms to 8 or 12, bound to tokens.

DecisionDate
P3CHERN-DECISIONPAR-014

Title and list text styles

Text styles match only 14–61% per module. Mobile is a size larger (text-sm/base, ShadCN h1/h2 titles). Web uses text-xs/sm and text-lg/bold panel titles.

Recommendation: agree a mapping table for screen title, section title, list primary text and list secondary text. Mobile can be one size larger by rule instead of by accident.
